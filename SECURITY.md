# Security policy

## Supported versions

CaP-X is research software under active development. Security fixes are applied to the latest
revision of the default branch; older commits and research snapshots are not supported.

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability. Use GitHub's
[private vulnerability reporting](https://github.com/capgym/cap-x/security/advisories/new) and
include a minimal reproduction, affected revision, impact, and any suggested mitigation.
Maintainers will acknowledge a report as soon as practical, investigate it, and coordinate a
fix and disclosure with the reporter.

## Execution and deployment warning

CaP-X intentionally executes Python generated by a model. The execution environment is not a
security sandbox and generated code may access the current process, filesystem, network, robot,
and credentials available to that process. Treat model output as untrusted code:

- run evaluations in a disposable container or isolated machine;
- expose only the devices, files, and network destinations the experiment requires;
- use scoped, short-lived API credentials and never place secrets in prompts or outputs;
- inspect generated policies before using them on physical hardware; and
- apply independent workspace, speed, force, and emergency-stop limits on real robots.

The web UI and model/perception servers are development services. Do not expose them directly
to an untrusted network without authentication and a hardened reverse proxy.

Third-party submodules and datasets follow their own security and support policies.
